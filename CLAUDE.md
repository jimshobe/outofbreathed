## Project direction

**Read `PLAN.md` first.** This repo rebuilt a Firebase/Vercel blog into a public family photo/video site on Cloudflare (Workers + D1 + R2), with optional Google sign-in for comments; built in phases. The plan defines the data model ("moments"), privacy rules (Private flag, location rounding, private zones, no kids' media off-site), iPhone Shortcut posting flow, and free-tier constraints. Work one phase at a time.

**The approved UI is the prototype in `mocks/index.html`** (with `mocks/shared.js` mock data). Build to match it: black background, plain white system monospace, `outofbreathed.com` title, a MapLibre 5 globe opening on Australia, and a plain chronological timeline. The site is not about the move to Australia; don't add move-centric features (day counters, "two homes", before/after framing). Preview it with `python3 -m http.server 8765` from `mocks/` (real family photos in `mocks/content/` are gitignored and must never be committed).

MapLibre gotchas found while prototyping: GeoJSON source URLs must be absolute (the worker can't resolve relative paths), and headless Chrome screenshots fire before GeoJSON workers finish, so delay capture when verifying map rendering.

  - Family app repo: `github.com/jimshobe/family` (cloned at `../family`). Vite/React PWA + Vercel functions, served at `family.outofbreathed.com` (CNAME `cname.vercel-dns.com`), with a daily Vercel cron (`/api/digest`).

## Architecture

Astro 7, `output: 'server'`, on Cloudflare Workers (`wrangler.jsonc`). Bindings come from `import { env } from 'cloudflare:workers'`, not `Astro.locals.runtime`.

- **Auth: viewing is public; Google sign-in is optional** (Cloudflare Access was removed on 2026-10-12). `src/lib/auth.ts` does OIDC code flow + PKCE (`/auth/login|callback|logout`), verifies the ID token (`src/lib/jwt.ts`), upserts `users`, and sets an HMAC-signed 30-day session cookie (`src/lib/signed.ts`, `SESSION_SECRET`) carrying id, email, first name and avatar, so pages need no DB read. The owner is whoever signs in with an `OWNER_EMAILS` address; middleware restricts `/post` and `/api/*` to them. In `astro dev`, requests act as the owner unless sent with `x-dev-viewer: anon` or `user:<id>:<email>:<name>`. Comments (`src/lib/comments.ts`, rules in `comment-rules.ts`) live at `/comments.json` (public read, signed-in write); a user's comments stay pending until the owner approves one, which sets `users.trusted`.
- **D1 `DB`** holds `moments` (`migrations/0001_moments.sql`, mirrors PLAN.md's data model). There is no Private flag, and locations are exact except inside **privacy zones** (`zones` table, `src/lib/zones.ts`, pure logic in `zone-math.ts`): there `display_lat/lng` is the zone's suburb centre and `moments.zone_id` is set. **All viewer queries must read the `moments_public` view**, which swaps a zoned moment's place name for the suburb and omits exact lat/lng; `recomputeZones()` reapplies zones after any zone change. Image files still have all location metadata stripped. Place names come from Nominatim reverse at zoom 18: "Venue, Suburb" when OSM names one, else the suburb. Categories: `moment_categories` holds all of a moment's categories (`moments.category` is the primary). `taken_at` is the camera's local time with offset; display the date part as written rather than converting zones, as dd-mm-yy (`fmtDay`). The UI shows no item counts and no month headers.
- **Sets** (`sets` table, `moments.set_id`) group an event's moments; one set per moment. `src/lib/timeline.ts` (pure, unit-tested) turns moments + sets into timeline entries: a set is one entry at its first date. Set pages are `/sets/[id]`; set CRUD is `/api/sets`. Ungrouping deletes the set, never its moments.
- **Timeline paging** (`timelinePage` in `src/lib/moments.ts`, `assemblePage` in `src/lib/timeline.ts`): ~120 moments per page extended to whole months via a `?before=<month start>` cursor; a set is shown whole on the page holding its first moment and left out of newer pages. Category filter `?c=` matches a moment's categories or any moment in its set (so sets stay whole). The year row jumps via `before=<year+1>-01-01T00:00:00`.
- **Lightbox** (`src/scripts/lightbox.ts`): pages embed photo-and-video lists with `LightboxData` (YouTube items play as an embedded player; on phones a video slide keeps ‹ › since swipes on the player go to YouTube) (`<script type=application/json data-lb-group>`) and mark openers with `data-lb-open`/`data-lb-id`. Browser scripts must cast DOM lookups (the Worker types in the shared tsconfig redefine `Element`).
- **Map** (`src/pages/map/`, `src/scripts/map.ts`): MapLibre 5 bundled from npm (globe projection), places = ~100 m spots (`round(display, 3)`, computed in SQL everywhere so keys match), pinned at their average position, embedded as JSON. Viewer JSON endpoints live under `/map/` (not `/api/`, which is owner-only): `place.json` (moments in a cell) and `go` (the Wikipedia ↗ redirect; article lookup in `src/lib/wikipedia.ts`, cached with the Cache API, which only works on a custom domain, from the spot's average position via `spotLookupPoint`). Nearby markers merge into a "+" group; tapping one zooms in (max 15), or, if its spots are within ~400 m, opens a combined panel (`merge` in map.ts). Markers are an HTML overlay anchored on their 7px square (anchoring on the whole element shifts them by half the label width).
- **Ride routes** (`src/lib/route.ts` pure + tested, `src/lib/routes.ts`): GPX uploaded per set via `/api/sets/:id/route`; the public `sets.route` JSON is simplified and has every point inside a privacy zone removed. Originals live under R2 `private/` (the `/media` route refuses that prefix); `recomputeZones()` re-trims routes too. Map style is shared in `src/scripts/map-style.ts` (globe `map.ts`, set page `setmap.ts`).
- **Posting form** (`src/components/PostForm.astro` + `src/scripts/post-form.ts`): a client-side queue; EXIF date/GPS are read from the original in the browser (`readJpegMeta`) and sent as `taken_at`/`lat`/`lng`, then the photo is shrunk on-device (`src/scripts/shrink.ts`, 2048 px, which drops all metadata) and uploaded 3 at a time with retries. Tags are optional (`CATEGORIES` has no catch-all; `moments.category` is nullable). Photos with GPS are grouped into ~100 m spots; each spot asks `/api/places/nearby` (`nearbyPlaces` in `src/lib/geo.ts`: Nominatim reverse + nearby venues from Overpass, raced across two public servers with a 6 s cap, plus Nominatim food searches one per second) and shows a place dropdown, defaulting to the nearest food place within 60 m when Nominatim's pick is just a building; the choice (or a typed "other…") is sent as `place_name`.
- **Post page** (`src/pages/post.astro`) is upload-only (PostForm). After posting it links to [edit these] (`/manage?ids=…` or the set's editor).
- **Manage** (owner-only, `/manage`): tabs `#photos|sets|settings`. Photos is a grid from `libraryPage` (`src/lib/manage.ts`, reads `moments` directly so zoned photos show their real place) with filters (`?f=noplace|noset`, `?tag=`, `?older=`, `?ids=`), [select] + bulk bar (`/api/moments/bulk`), and the photo editor sheet (`src/scripts/photo-editor.ts` + `EditorSheet.astro`; GET/PATCH/DELETE `/api/moments/:id`; `?edit=<id>` opens it). Sets lists sets newest first with [+ new set] (opens the new set's editor with the photo picker, `?add=1`); the photos bulk bar's set menu also has "+ new set…". Each set opens `/manage/sets/<id>`: title, caption, place for all, route, photos in order with reorder (drag or ‹ ›, `PUT /api/sets/:id/order` → `moments.set_pos`, migration 0015), take out, add from the library, ungroup. Settings holds comments, privacy zones and place links. Owners see [edit] on timeline photos (`/manage?edit=`), set cards and set pages (`/manage/sets/`).
- **Set order**: `set_pos` (NULL after joining a set) then time, via `setOrder` in `src/lib/timeline.ts`; a set's dates still come from its earliest/latest photo.
- **Place links** (`src/lib/maps-link.ts`, rendered by `src/components/PlaceLinks.astro` and the map panel heading): each part of a place name opens our map and has a ↗ that leaves the site. A venue ("Venue, Suburb", not zoned) is two parts: venue ↗ → Google Maps search, suburb ↗ → Wikipedia. Other places → Wikipedia. Wikipedia ↗s go via `/map/go`, which redirects to the article (for venues the suburb's, found by `areaTitle`), or Google Maps if none. The site shows no Wikipedia content itself (the in-panel summary was tried and dropped).
- **Place link overrides** (`place_links` table, `src/lib/place-links.ts`, `/api/place-links`): per place name (as viewers see it), an owner-pasted `gmaps_url` (venue ↗) and/or `wiki_url` (suburb/place ↗) replace the automatic targets; loaded once per request via `placeLinksFor(Astro.locals)` and embedded in the map's places JSON. Edited in /manage → settings → place links. Place names are fixed in /manage: per photo (photo editor), per selection (bulk [rename]) or per set (set editor's place field, which suggests nearby venues).
- **Videos are YouTube-only** (unlisted links, embedded via youtube-nocookie); the upload API rejects video files. Posts without GPS (YouTube links, Safari-stripped photos) get their position by geocoding a typed place name (`geocodePlace` in `src/lib/geo.ts`, Nominatim).
- **R2 `MEDIA`** holds photos, served only via `src/pages/media/[...key].ts` (behind middleware, Range support for video, `Cache-Control: private`). Never hand out public R2 URLs.
- The adapter also provisioned a `SESSION` KV namespace and an `IMAGES` binding on first deploy; they're unused so far.
- Seed/test data lives in gitignored `.wrangler/seed/`. The only moment so far is `test-0001` (`test/forest.jpg`), a placeholder.
